# Координаты фигур и 3D-расстановка

Этап `localize` работает с готовыми весами YOLO detect и выбранными GLB.
Нового обучения, генерации датасета и изменения моделей он не требует.

## Запуск в Studio

1. Откройте проект, в котором находятся обученные веса и исходные артефакты
   датасета и выбранных моделей. Перейдите в «Проверка → Координаты и 3D-сцена».
2. Выберите результат обучения и фото, видео либо папку изображений.
3. Введите ширину и высоту калибровочного изображения, `fx`, `fy`, `cx`, `cy`.
   Это параметры **исходного кадра**, не внутреннего изображения YOLO после letterbox.
   Подсказки рядом с полями объясняют величины и способы получения значений.
4. Укажите плоское изображение карты и её размеры в метрах.
5. Выберите регистрацию по текстуре либо укажите четыре угла на первом кадре.
   Порядок соответствует углам исходной карты: верхний левый, верхний правый,
   нижний правый, нижний левый. Не сортируйте углы по положению на экране.
6. Запустите «Восстановить расстановку фигур» и откройте результат.

Результат показывает проекцию моделей на фотографию, круги на карте, 3D-сцену
и таблицу координат. В 3D можно переключиться на вид сверху.
Зелёные круги обозначают оценки, оранжевые — неоднозначные оценки.
Отказы регистрации сохраняются и показываются отдельно; эталонная камера
Blender не подставляется при отказе.

## Камера и карта

Для текущих квадратных рендеров 1152 × 1152 с FOV 45°, квадратными пикселями
и отсутствием camera shift: `fx = fy ≈ 1390.587`, `cx = cy = 576`, дисторсия нулевая.
Эти значения являются примером, а не универсальной калибровкой реальной камеры.

Внутренние параметры задаются пользователем, положение камеры восстанавливается
из изображения. При пропорциональном resize матрица K масштабируется автоматически.
Несовпадение пропорций кадра и калибровки отклоняется: crop требует отдельной K.
Для реального объектива коэффициенты дисторсии берутся из калибровки OpenCV.

Автоматическая регистрация сопоставляет SIFT-детали исходной карты и кадра,
отбирает совпадения RANSAC и оценивает камеру по точкам плоскости.
Требуются не менее 10 согласованных совпадений, покрывающих не менее 4% карты.
Ошибка проекции не должна превышать 5 px. Эти проверки отбрасывают часть ошибок,
но не гарантируют уникальность регистрации на повторяющемся рисунке.

Ручные углы подходят для одного фото либо видео с явно неподвижной камерой.
В автоматическом режиме флаг «Камера неподвижна» сохраняет первую успешную
регистрацию в пределах одного файла видео. Для следующего файла камера оценивается
заново. При движении камеры этот флаг нужно выключить.

## Геометрия и размеры

Модели и порядок классов берутся из снимка проекта в датасете обучения,
а не из текущего выбора моделей для новых сцен. Названия классов проверяются
против весов YOLO. Исходные артефакты не изменяются; GLB копируются в результат.

Программа воспроизводит преобразование GLB из Y-up в систему Blender,
центрирование по габаритам и масштабирование по высоте. Радиус и смещение центра
основания оцениваются по нижней горизонтальной поверхности: площадь почти
горизонтальных треугольников группируется по высоте в нижних 10% модели.
Выбирается самая низкая группа с площадью не меньше 20% максимальной группы.
Её окрестность задаёт контур для описывающего круга. При отсутствии такой поверхности
используются нижние 2% вершин. Это геометрическая оценка, не физическое измерение.

Для ручного уточнения есть `localization.base_overrides` в полной конфигурации:

```yaml
localization:
  base_overrides:
    obj_02:
      height_m: 0.05
      center_xy_m: [0.001, 0.002]
      radius_m: 0.023
```

`center_xy_m` задаётся в локальной системе уже масштабированной и центрированной
модели: X вправо, Y вперёд, Z вверх, до поворота фигуры на поле.
Для реальных фигур задайте измеренные размеры: условные 5 см из синтетического
генератора не становятся измерением реальной фигурки.

Для локализации перебираются повороты с шагом 15°, положение ограничивается
границами поля, лучшие варианты уточняются непрерывной оптимизацией.
Сравниваются центр и размеры bbox, используется устойчивая функция ошибки.
Выпуклая оболочка сохраняет крайние точки проекции и сокращает вычисления.
Детали исходной карты и геометрия моделей рассчитываются один раз на запуск.

## Формат результата

Система поля: метры, начало в центре, X вправо, Y к верхнему краю исходной карты,
Z вверх. `xy_m` — центр оценённого основания. `placement_xy_m` — положение
центрированной GLB. Они могут отличаться. `yaw_deg` — гипотеза подгонки;
`yaw_observed: false` запрещает считать её достоверно измеренной ориентацией.

`scene.json` содержит карту, модели, их происхождение и кадры галереи.
`frames.jsonl` содержит все обработанные кадры: источник, исходный номер кадра,
время по FPS, камеру, рамки, координаты, радиусы и статусы.
Для фото временная метка отсутствует. `video_stride=5` обрабатывает кадры 0, 5, 10
и далее; промежуточные положения не интерполируются. Лимит галереи не ограничивает
число строк в JSONL. Постоянные идентификаторы фигур между кадрами пока не назначаются.

## Воспроизводимая проверка

```bash
.venv/bin/python -m boardgen.maintenance.localization_benchmark \
  --dataset /path/to/dataset/artifact \
  --predictions /path/to/evaluation/artifact/predictions.json \
  --output /path/to/new/results \
  --camera-mode template
```

Команда читает сохранённые предсказания и выбирает непустые сцены на поле:
confidence ≥ 0.50, правильный класс и IoU ≥ 0.85 для каждого объекта,
без пропусков и лишних обнаружений. `template` восстанавливает положение камеры
из изображения; из Blender берётся только известная внутренняя калибровка.
`oracle` использует эталонную камеру для отдельной проверки подгонки фигур.
Эталонное размещение применяется только при расчёте ошибок.

Отчёт, изображения наложений, карты, GLB и координаты сохраняются в новой папке.
Сводка эксперимента находится в `research/localization/results.json`.
Это условная оценка на успешных синтетических детекциях, а не качество на всех
кадрах или реальной партии. Центры оснований сравниваются с тем же геометрическим
определением на эталонно размещённой GLB; независимой ручной разметки оснований нет.

## Ограничения

- Метод предполагает вертикальные фигуры известного размера на одной плоскости.
- Перекрытая или неправильно классифицированная фигура может получить неверную
  координату даже при хорошем совпадении bbox.
- Несколько ориентаций могут объяснять одну рамку. `position_spread_m` отражает
  разброс найденных гипотез, не полную погрешность измерения.
- Пропущенные YOLO фигуры не восстанавливаются. Руки и движение камеры не анализируются.
- Подиумы не входят в геометрический эксперимент: у них другая высота поверхности.
